# Workflow notes

Assessment reviewers read `AI_WORKFLOW.md` to understand _how_ the work was done with AI, not
only what was built. The raw transcripts are complete but long. This entry is the guided tour:
what was attempted, where the AI needed correcting, and which prompts or harness pieces made the
difference. An entry that only lists successes is less useful and less credible than one that
records mistakes and course corrections.

## What this skill does and doesn't touch

- **Writes:** one new entry appended at the end of the `## Session log` section of
  `AI_WORKFLOW.md`, plus small fixes to the harness table there if this session changed the harness.
- **Never touches** `ai/sessions/` (the transcripts and `README.md` index belong to the SessionEnd
  hook) or any other file.

## Steps

1. Identify the session:
   `node .claude/skills/workflow-notes/scripts/current-session.mjs` prints `sessionId`, `date`
   and `sessionFile`. The file at `sessionFile` is written when the session ends, so linking to it
   now is correct even though it doesn't exist yet.
2. If an entry for this `sessionId` already exists in the log (e.g. the skill ran earlier in the
   same session), update that entry instead of adding a second one.
3. Reconstruct the session from the conversation: the user's requests, decisions made, commits
   (`git log --oneline` since the session started), and any hook/reviewer feedback that changed
   the course.
4. Append the entry using the template below. Keep it to roughly 10–25 lines. Be specific (file
   names, story IDs, the actual error) and plain. No marketing tone.

## Entry template

```markdown
### <date> · <short title of what the session achieved>

Session: [`<first 8 chars of id>`](ai/sessions/<date>-<sessionId>.md) · Stories: <S-ids or "harness">

**Goal:** <one sentence, in the user's terms>

**What the AI did:**

- <main steps and outcomes, with file paths / story IDs>

**Corrections & surprises:**

- <where the user redirected the AI, what the AI got wrong, what a hook/reviewer caught; say
  "none" only if truly none>

**Prompts worth noting:**

- "<short quote of a user prompt that shaped the result>" — <why it mattered>

**Harness changes:** <skills/hooks/agents/CLAUDE.md edits this session, or "none">
```

Quote the user's prompts briefly and accurately. Paraphrasing them into stronger claims
misrepresents the session. Emails, keys and personal details never go in the entry. The
transcripts are redacted, and this file should be too.
